## 1. เป้าหมายของ Sprint 4

คู่มือรายวิชากำหนดรอบสุดท้ายเป็น **DevOps, CI/CD & AI Integration**: จัดทำระบบทดสอบอัตโนมัติ (Automated Testing) ตั้งค่า CI/CD Pipeline ผ่าน GitHub Actions และเชื่อมต่อฟีเจอร์ AI (การทำงานตามความเชี่ยวชาญเฉพาะบุคคล)

รอบนี้เลือกสาย **AI Integration** เป็นงานใหม่หลัก และ **ไม่รวมงานขึ้นเซิร์ฟเวอร์จริง (deploy)** ในรอบนี้ — เพิ่ม **2 ฟีเจอร์ AI ที่ทำงานจริง** ให้เว็บแอป:

1. **ผู้ช่วยแนะนำ (AI Recommender)** — หน้าใหม่: เลือกหนังตั้งต้นจากลิสต์ของผู้ใช้ (หรือมาจากหน้ารายละเอียด) + พิมพ์โจทย์สั้น ๆ ได้ตามใจ → ระบบดึงหนังคล้ายจริงจาก TMDB → AI คัดเหลือ 3–5 เรื่อง พร้อม **เหตุผลภาษาไทย** รายเรื่อง + ปุ่มเพิ่มเข้าลิสต์ (Smart Agent Workflow: ค้นหา → คัดกรอง → จัดอันดับ → เสนอ → เพิ่มเข้าลิสต์)
2. **สรุปไทย (AI Movie Summary)** — ในหน้ารายละเอียดหนัง: ปุ่มสร้าง "สรุปเนื้อเรื่อง + ทำไมควรดู" ภาษาไทย จากข้อมูล TMDB ที่มีอยู่แล้ว (สร้างครั้งเดียว เก็บแคช — เปิดซ้ำไม่เรียก AI ซ้ำ)

หลักการเดิมทั้งหมดคงอยู่: **ทดสอบออฟไลน์ 100%** (ไม่ใช้เน็ต/ไม่ใช้คีย์) · ไม่มีคีย์ก็ใช้งานระบบเดิมได้ครบ · ไม่แก้โค้ดและเทสต์ชุดเดิม · CI เขียวต่อเนื่อง · คีย์ทั้งหมดผ่านตัวแปรสภาพแวดล้อมเท่านั้น

**การเทียบกับเกณฑ์ส่วนที่ 5 ของการนำเสนอ (15%)** — "CI/CD Pipeline และแนวโน้ม AI Integration": แสดง Pipeline ที่ทำงานจริงบน GitHub Actions (ชุดเดิม ต่อยอดด้วยเทสต์รอบใหม่) + สาธิตฟีเจอร์ AI จริง 2 ตัว + แนวทางต่อยอด (ค้นหาเชิงความหมาย · ขึ้นเซิร์ฟเวอร์จริง ฯลฯ)

## 3. สถาปัตยกรรมเป้าหมาย

โครง 3 ชั้นเดิมคงอยู่ทั้งหมด — เพิ่มโมดูล AI เข้าชั้นที่มีอยู่แล้ว ไม่สร้างชั้นใหม่:

```
  ชั้นนำเสนอ (Presentation)      web/ — เพิ่มหน้า "ผู้ช่วยแนะนำ" + ส่วนสรุปไทยในหน้ารายละเอียด
        │
        ▼
  ชั้นตรรกะธุรกิจ (Business)      discovery.py · watchlist.py · ai_advisor.py (ใหม่)
        │
        ▼
  ชั้นเข้าถึงข้อมูล (Data)        tmdb_client.py · movie_store.py · exporter.py · ai_client.py (ใหม่)
        │
        ▼
   TMDB API            data/movies.db (รวมแคช AI ในตาราง api_cache)            ผู้ให้บริการ AI (DeepSeek API)
```

*ภาพที่ 1 — โครงสร้าง 3 ชั้นและตำแหน่งของโมดูล AI*

- **ai_client.py (ชั้นเข้าถึงข้อมูล)** — คุยกับผู้ให้บริการ AI ผ่าน `requests` แบบเดียวกับ tmdb_client: อ่านคีย์จาก env · กำหนดเวลาเกิน · ปิดโหมดคิดของโมเดล · บังคับคำตอบเป็น JSON · แปลงข้อผิดพลาดเป็น `AiError` (401/429/หมดเวลา/รูปแบบคำตอบ) พร้อมข้อความไทยกลางที่เว็บนำไปใช้ต่อ
- **ai_advisor.py (ชั้นตรรกะธุรกิจ)** — ประกอบคำขอจากข้อมูลหนังจริง (ผ่าน discovery/movie_store เดิม) · ตรวจคำตอบก่อนใช้ (id ต้องอยู่ในชุดที่ส่งไปเท่านั้น · ความยาวพอเหมาะ) · จัดการแคชสรุป · เมื่อไม่มีคีย์หรือ AI ล่ม จะส่งสัญญาณให้ชั้นเว็บแสดงผลแบบสุภาพ
- การฉีดพึ่งพา (dependency injection) คงเดิม — เทสต์ใส่ **ตัวจำลอง AI** ได้ ไม่ต้องใช้เน็ต/คีย์
- แคช: ใช้ตาราง `api_cache` เดิมกับคีย์นำหน้า `ai:` (รายละเอียดหัวข้อที่ 5) — ถ้าเมธอดแคชเดิมบังคับอายุคงที่ จะเพิ่มพารามิเตอร์อายุที่จุดเดียวพร้อมเทสต์
- การตรวจเชิงกลไกตอนปิดรอบ (แบบ Sprint 2–3): กฎเดิม R1–R6 ยังใช้ทั้งหมด โดย **ปรับ R4** — `requests` อนุญาตเฉพาะโมดูลไคลเอนต์ภายนอก 2 ตัว (tmdb_client · ai_client) — จะรันตรวจชุดใหม่ตอนปิดรอบและบันทึกผลจริง

## 4. ฟีเจอร์ใหม่ — พฤติกรรมที่ต้องเกิด

### 4.1 ผู้ช่วยแนะนำ (หน้า `/ai/recommend`)

- **ทางเข้า:** ลิงก์เมนู "ผู้ช่วยแนะนำ" ทุกหน้า · ปุ่ม "ใช้เรื่องนี้เป็นฐาน" ในหน้ารายละเอียดหนัง
- **ฟอร์ม:** เลือกหนังตั้งต้น — จากรายการรับชม/รายการโปรดของผู้ใช้ (ดรอปดาวน์) — + ช่องโจทย์อิสระ (ไม่บังคับ เช่น "อยากดูเบา ๆ ตลก ๆ") — ถ้าลิสต์ว่างทั้งคู่ แสดงข้อความชวนไปเพิ่มรายการจากหน้าค้นหา + ลิงก์
- **ขั้นตอน:** กดปุ่ม → ระบบดึงหนังคล้ายของเรื่องตั้งต้นจาก TMDB (กลไกเดิม จำกัด 12 เรื่อง) → ส่งให้ AI คัด 3–5 เรื่องพร้อมเหตุผลไทย → แสดงการ์ด (โปสเตอร์ · ชื่อ · ปี · คะแนน · เหตุผล) + ปุ่ม "เพิ่มเข้ารายการรับชม" (กลไกปุ่มเดิมทั้งเว็บ: กด → บันทึก → กลับหน้าเดิม + ข้อความยืนยัน)
- **คำตอบ AI:** บังคับรูปแบบ JSON (id + เหตุผล) — **ตรวจก่อนใช้เสมอ**: id ต้องอยู่ในชุดที่ส่งไป · เหตุผลไม่ว่างและมีความยาวพอเหมาะ · ตัดส่วนเกินออกก่อนบันทึกแคช
- **ความปลอดภัยของคำสั่ง:** ข้อความโจทย์ของผู้ใช้ถูกส่งเป็น "ข้อมูล" ในคำขอ (ระบบกำกับให้โมเดลไม่ทำตามคำสั่งที่แฝงในข้อมูล) และทุกข้อความจาก AI ถูก escape ตอนแสดงผลเหมือนอินพุตอื่นทั้งเว็บ
- **ไม่มีคีย์ AI:** หน้าแสดงวิธีตั้งค่าคีย์ + แสดงหนังคล้ายพื้นฐาน (เรียงตามคะแนนด้วยกลไกเดิม) โดยไม่ใช้ AI — ระบบไม่พัง (แบบเดียวกับโหมดไม่มีคีย์ TMDB)

### 4.2 สรุปไทย (ในหน้า `/movie/<id>`)

- **ปุ่ม "สร้างสรุปภาษาไทย (AI)"** → สร้าง "สรุปเนื้อเรื่อง 2–3 ประโยค + ทำไมควรดู 3 ข้อ" จากชื่อหนัง/ปี/แนว/เรื่องย่อที่มีอยู่แล้ว → เก็บแคช → กลับหน้าเดิมพร้อมข้อความยืนยัน (แบบ POST → 303 → หน้าเดิม เหมือนปุ่มอื่นทั้งเว็บ)
- **เปิดหน้ารายละเอียดครั้งถัดไป:** ถ้ามีแคชแล้ว แสดงส่วน "สรุปโดย AI" ทันที — ไม่เรียก AI ซ้ำ (ทั้งประหยัดเวลาและค่าใช้จ่าย)
- **ไม่มีคีย์:** ไม่แสดงปุ่ม + แบนเนอร์วิธีตั้งค่า (แบบเดียวกับ TMDB)
- **AI ล่ม:** ข้อความสุภาพ บอกสาเหตุ + ลองใหม่ได้ — และ **ไม่บันทึกแคช**

## 5. แคชและค่าใช้จ่าย

- คีย์แคชในตาราง `api_cache` (เดิม): สรุป = `ai:summary:<movie_id>` อายุ 7 วัน · แนะนำ = `ai:recommend:<base_id>:<ลายนิ้วมือโจทย์>` อายุ 1 ชั่วโมง (นำหน้า `ai:` เพื่อแยกจากแคช TMDB)
- ค่าใช้จ่ายประมาณการ: **~1.5–2 สตางค์ต่อ 1 ครั้ง** (ช่วงปกติ) — ทดสอบ + ซ้อมเดโมรวมกัน ~200 ครั้ง ≈ **4 บาท** (ช่วงพีกสูงสุด ≈ 8 บาท)
- ข้อมูลผู้ให้บริการ AI ณ วันวางแผน (4/10/69 — จากเอกสารทางการ): ชื่อโมเดลที่ใช้จริง `deepseek-flash` (รุ่น V4.1-Flash) · ราคา $0.15 อินพุต / $0.60 เอาต์พุต ต่อ 1 ล้านโทเคน ช่วงปกติ (ช่วงพีก จ.–ศ. 08:00–11:00 และ 13:00–17:00 น. เวลาไทย คูณ 2 · เสาร์–อาทิตย์ = ราคาปกติทั้งวัน) · รองรับ JSON output · โหมดคิดถูกเปิดโดยค่าเริ่มต้น — ต้องปิดในคำขอเพื่อความเร็วและค่าใช้จ่ายต่ำ · เรียกผ่าน `requests` ตรง ๆ ได้ (รูปแบบเข้ากันได้กับ OpenAI) ไม่เพิ่มไลบรารี · **ไม่มี embeddings** (ผลกับแนวทางต่อยอด)

## 6. กรณีขอบเขต (Edge Cases)

| สถานการณ์ | ระบบทำอะไร | พิสูจน์ด้วย |
|---|---|---|
| ไม่มีคีย์ AI | ทุกหน้าเปิดได้ · หน้าแนะนำแสดงหนังคล้ายพื้นฐาน (จัดอันดับด้วยคะแนนเดิม) + แบนเนอร์วิธีตั้งค่า · ปุ่มสรุปไม่แสดง | เทสต์ + รันจริง |
| คีย์ผิด (401) | ข้อความสุภาพ "คีย์ AI ไม่ถูกต้อง" + กลับหน้าเดิมได้ | เทสต์ |
| เรียกถี่เกิน (429) | ข้อความ "เรียกบ่อยเกินไป ลองใหม่ภายหลัง" | เทสต์ |
| AI หมดเวลา / เน็ตหลุด | ข้อความสุภาพ บอกสาเหตุ + ลองใหม่ได้ | เทสต์ |
| AI ตอบไม่ใช่ JSON | "AI ตอบผิดรูปแบบ — ลองใหม่" ไม่บันทึกแคช ไม่พัง | เทสต์ |
| AI อ้าง id นอกชุดที่ให้ | คัดเฉพาะ id ที่ถูกต้อง · ถ้าไม่เหลือ = ข้อความลองใหม่ | เทสต์ |
| หนังคล้ายไม่พอ (ได้ 0 เรื่อง) | ข้อความ "ยังมีข้อมูลไม่พอจะแนะนำ" | เทสต์ |
| โจทย์ว่าง | ทำงานปกติ (แนะนำจากเรื่องตั้งต้นล้วน) | เทสต์ |
| โจทย์ยาวเกิน 200 ตัวอักษร | ตัดให้อัตโนมัติ + แจ้งว่าใช้เฉพาะส่วนแรก | เทสต์ |
| โจทย์ emoji / ไทย / โค้ด | ทำงานได้หรือแจ้งชัดเจน — โค้ดถูก escape ตอนแสดงผล | เทสต์ |
| เข้าหน้าแนะนำขณะทุกลิสต์ว่าง | ข้อความชวนไปเพิ่มรายการ + ลิงก์หน้าค้นหา | เทสต์ |
| กดสร้างสรุปซ้ำ | ใช้แคชเดิม ไม่เรียก AI ซ้ำ | เทสต์ + รันจริง |
| สร้างสรุปขณะ AI ล่ม | ไม่บันทึกแคช + ข้อความสุภาพ | เทสต์ |
| ไฟล์ฐานข้อมูลเสีย | หน้าซ่อมเดิม (ไม่กระทบ) | ของเดิม |
