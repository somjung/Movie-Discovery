## 1. เป้าหมายของ Sprint 3

คู่มือรายวิชากำหนด Sprint 3 เป็น Full-Stack App Dev: การเชื่อมต่อ Front-End และ Back-End เข้าด้วยกันอย่างสมบูรณ์ · การจัดการ State · การสอดคล้องของข้อมูล · การรับมือกรณีขอบเขต (Edge Cases)

Sprint นี้จึงสร้างส่วนปฏิสัมพันธ์กับผู้ใช้ (Presentation Layer) ใหม่เป็น **เว็บแอปพลิเคชัน** (คู่มืออนุญาต "CLI หรือ GUI") โดยเชื่อมกับ Business Logic และ Data Access เดิมทั้งหมดของ Sprint 1–2 — พร้อมเพิ่ม **ระบบเล่นภาพยนตร์ (Player)** เล่นหนังได้จริง 1 เรื่อง

- เว็บแอป Flask — ค้นหา · ดูรายละเอียด · กรอง/เรียงหนังคล้าย · จัดการรายการรับชม/รายการโปรด · ประวัติ · ดาวน์โหลด CSV
- Player เล่นภาพยนตร์ 1 เรื่องผ่านวิดีโอของเบราว์เซอร์ — หนังคลาสสิกสาธารณสมบัติ Night of the Living Dead (1968)
- การจัดการ State และความสอดคล้องของข้อมูลในมุมมองเว็บ (จำนวนรายการ · ป้ายไขว้ลิสต์ · ข้อมูลชุดเดียวกับ CLI)
- Edge Cases ครบทั้งระบบ: คีย์หาย · เน็ตหลุด · ฐานข้อมูลเสีย · ไฟล์หนังหาย · URL ผิด
- ชุดทดสอบอัตโนมัติต่อยอด (Flask test client + ตัวจำลองเดิม) และ CI เขียวต่อเนื่อง

## 3. สถาปัตยกรรมเป้าหมาย

โครง 3 ชั้นของ Sprint 1–2 คงอยู่ทั้งหมด — Sprint 3 เปลี่ยนเฉพาะชั้น Presentation:

```
  Presentation Layer (ใหม่)    web/ — หน้าเว็บ Flask + เสิร์ฟวิดีโอ
        │ เรียกใช้เมธอดของบริการโดยตรง (โปรเซสเดียวกัน)
        ▼
  Business Logic Layer (เดิม)  discovery.py · watchlist.py
        ▲
        │
  Data Access Layer (เดิม)     movie_store.py · tmdb_client.py · exporter.py
```

- เว็บนำเข้า (import) โมดูลเดิมจาก `src/` โดยไม่คัดลอกตรรกะซ้ำ — ไม่แก้ `src/` ยกเว้นกรณีจำเป็นที่ต้องบันทึกเหตุผลไว้
- ข้อกำหนดการออกแบบเว็บ: สร้างชุดบริการ (service + การเชื่อมต่อ SQLite) ใหม่ต่อ 1 คำขอ แล้วปิดเมื่อจบคำขอ — เพราะ Python sqlite3 ผูกการเชื่อมต่อกับ thread ที่สร้าง และเซิร์ฟเวอร์เว็บจัดการคำขอใน worker thread (CLI เดิมไม่กระทบ — ทำงาน thread เดียว)
- CLI เดิมยังใช้งานได้ (ใช้บริการชุดเดียวกัน) และฐานข้อมูลชุดเดียวกัน `data/movies.db`
- การจัดเก็บโค้ด: แต่ละรอบ Sprint เก็บโค้ดเวอร์ชันปิดรอบของตัวเองไว้ในโฟลเดอร์ของรอบนั้น — โค้ดเวอร์ชันล่าสุด (พัฒนาต่อจาก Sprint 2) อยู่ที่:

```
  sprint3/script-final-project/
  ├── src/            (เดิม ไม่แก้)
  ├── tests/          (เดิม + test_web.py ใหม่)
  ├── web/            (ใหม่)  __init__.py · routes.py · templates/ · static/
  ├── scripts/        (ใหม่)  fetch_demo_video.py
  └── data/videos/    (ใหม่)  ไฟล์หนัง — ไม่เข้า git
```

## 4. หน้าจอและเส้นทาง (Route Specification)

| เส้นทาง | หน้าที่ |
|---|---|
| GET / | หน้าแรก: ช่องค้นหา · ลิงก์ทุกหน้า · จำนวนรายการรับชม/โปรดบนแถบนำทาง · แบนเนอร์วิธีตั้งค่าคีย์เมื่อไม่มีคีย์ |
| GET /search?q= | ผลค้นหา (การ์ดหนัง: โปสเตอร์ · ชื่อ · ปี · คะแนน) · บันทึกประวัติอัตโนมัติ |
| GET /movie/&lt;id&gt; | รายละเอียดหนัง + หนังคล้ายกัน พร้อมตัวกรองเหมือน CLI (min-rating · min-votes · year · sort · limit) + ปุ่มเพิ่ม/ลบสองลิสต์ |
| POST /watchlist/add/&lt;id&gt; · /watchlist/remove/&lt;id&gt; · /watchlist/clear | จัดการรายการรับชมจากหน้าเว็บ แล้วกลับหน้าที่ยืนยันผล |
| POST /favorites/add/&lt;id&gt; · /favorites/remove/&lt;id&gt; | จัดการรายการโปรดจากหน้าเว็บ |
| GET /watchlist · GET /favorites | แสดงลิสต์ + ป้าย ★ + ปุ่มดาวน์โหลด CSV + ปุ่มลบรายรายการ |
| GET /export/&lt;kind&gt; | ดาวน์โหลดไฟล์ CSV (watchlist / favorites) — ใช้ Exporter เดิม |
| GET /history | ประวัติการค้นหาล่าสุด |
| GET /play/&lt;id&gt; | หน้า Player — เล่นได้เฉพาะหนังที่มีไฟล์ (ปัจจุบัน 10331) เรื่องอื่นแจ้ง "ยังไม่มีไฟล์สำหรับเรื่องนี้" |
| GET /media/&lt;name&gt; | เสิร์ฟไฟล์วิดีโอในเครื่อง (รองรับ Range เพื่อเลื่อน seek ได้) |
| — | 404 / 500 → หน้าแจ้งข้อผิดพลาดสุภาพ |

โหมดการทำงาน: ฟอร์มแบบ postback ที่เซิร์ฟเวอร์เรนเดอร์ เป็นหลัก — ไม่ใช้เฟรมเวิร์กฝั่งหน้า ไม่มีสคริปต์ภายนอก

หนัง: **Night of the Living Dead (1968)** — คลาสสิกสาธารณสมบัติ TMDB id 10331 (ค้นเจอภายในแอปเองได้)

## 6. การจัดการ State และความสอดคล้องของข้อมูล

- State: แถบนำทางทุกหน้าแสดงจำนวน "รายการรับชม (N) · รายการโปรด (M)" จากฐานข้อมูลจริง — อัปเดตทันทีหลังทุกการเพิ่ม/ลบ
- ความสอดคล้อง: ป้าย ★ แสดงเมื่อเรื่องนั้นอยู่ในอีกลิสต์ด้วย · ไฟล์ CSV ที่ดาวน์โหลดตรงกับลิสต์ ณ เวลากดเสมอ · ผลค้นหา/หนังคล้ายใช้แคชชุดเดียวกับ CLI · ทุกแถวในสองลิสต์มีข้อมูลหนังรองรับ (กลไกเดิมของ Sprint 2)
- จุดสาธิต: เพิ่มรายการจากหน้าเว็บ → เปิด CLI เห็นรายการเดียวกันทันที (ฐานข้อมูลชุดเดียว)

## 7. กรณีขอบเขต (Edge Cases)

| กรณี | พฤติกรรมที่ต้องเกิด | พิสูจน์ด้วย |
|---|---|---|
| ไม่มีคีย์ TMDB | ทุกหน้าเปิดได้ · หน้าค้นหาแจ้งวิธีตั้งค่าคีย์ · หน้าออฟไลน์ (ลิสต์/ประวัติ/CSV) ใช้ได้ปกติ | เทสต์ + รันจริง |
| TMDB ล่ม / timeout | หน้าแจ้งสุภาพ + ลองใหม่ได้ · ถ้าแคชยังสด แสดงผลจากแคชได้ | เทสต์ + รันจริง |
| คีย์ผิด (401) / เรียกถี่เกิน (429) | ข้อความอธิบายชัดเจนตามแบบ Sprint 2 | เทสต์ |
| คำค้นว่าง / ยาว / ไทย / emoji / อักขระพิเศษ | ค้นได้หรือแจ้ง "ไม่พบ" — ไม่พัง | เทสต์ |
| รหัสหนังไม่มีจริง (404) | หน้า "ไม่พบภาพยนตร์" สุภาพ | เทสต์ |
| ไฟล์ฐานข้อมูลเสีย | หน้าแจ้งปัญหา + วิธีแก้ (ย้าย/ลบไฟล์แล้วเริ่มใหม่) | รันจริง (จำลอง) |
| ไฟล์วิดีโอหาย | หน้า Player แจ้งวิธีโหลด ไม่ล้ม | เทสต์ + รันจริง |
| เพิ่มซ้ำ / ลบของที่ไม่มี | ข้อความแจ้งผลชัดเจน ไม่ error | เทสต์ |
| URL ไม่มีอยู่ | หน้า 404 สุภาพ | เทสต์ |
| ลิสต์ว่าง + กดดาวน์โหลด | ได้ไฟล์หัวตาราง + แจ้งจำนวน 0 | เทสต์ |

## 8. Definition of Done (DoD)

**การทำงานปกติ**

- [ ] เปิดเซิร์ฟเวอร์แล้วเข้าเว็บได้ครบทุกหน้า (หน้าแรก · ค้นหา · รายละเอียด · 2 ลิสต์ · ประวัติ · Player)
- [ ] ค้นหาจริงกับ TMDB ผ่านหน้าเว็บ — ผลถูกต้อง และบันทึกประวัติในตาราง `searches`
- [ ] ตัวกรองหนังคล้าย (คะแนน · โหวต · ปี · เรียง · จำนวน) ทำงานบนเว็บเทียบเท่า CLI
- [ ] เพิ่ม/ลบ/เคลียร์ทั้งสองรายการผ่านเว็บ · ไม่เพิ่มซ้ำ
- [ ] ป้าย ★ ไขว้ลิสต์แสดงถูกต้องทั้งสองหน้า
- [ ] ดาวน์โหลด CSV ได้ เนื้อหาตรงกับรายการปัจจุบัน
- [ ] **Player เล่นหนังได้จริง** — เปิด /play/10331 แล้ววิดีโอเล่นได้ เลื่อน seek ได้ (ยืนยันด้วยการทดสอบจริงบนเบราว์เซอร์)
- [ ] เพิ่มรายการจากหน้าเว็บ → เปิด CLI เห็นข้อมูลเดียวกัน (และกลับกัน)
- [ ] รีสตาร์ทเซิร์ฟเวอร์แล้วข้อมูลยังอยู่ครบ

**กรณีผิดพลาดและขอบเขต** — ครบทุกข้อในตารางหัวข้อที่ 7
