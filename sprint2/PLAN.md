## 1. เป้าหมายของ Sprint 2

Sprint นี้พัฒนาส่วน Business Logic และ Data Access ของโปรแกรม ให้ทำงานกับข้อมูลจริงจาก TMDB API และจัดเก็บข้อมูลอย่างยั่งยืนในฐานข้อมูล SQLite ประกอบด้วย

- เชื่อมต่อ TMDB API จริง — จัดการข้อผิดพลาดครบทุกกรณี และแคชผลลัพธ์ไว้ในตาราง `api_cache`
- ฐานข้อมูล SQLite 6 ตาราง — `movies` · `similar_links` · `watchlist` · `favorites` · `searches` · `api_cache`
- ฟังก์ชันค้นหา (Searching) กรองข้อมูล (Filtering) และเรียงลำดับ (Sorting) ทำงานกับข้อมูลจริง
- การจัดการ File I/O — ส่งออกรายการรับชมและรายการโปรดเป็นไฟล์ CSV
- ชุดทดสอบอัตโนมัติแบบ Mock API ต่อยอด CI เดิมให้เขียวต่อเนื่อง

## 3. โครงสร้างข้อมูล (SQLite 6 ตาราง)

| ตาราง | คีย์หลัก | หน้าที่ |
|---|---|---|
| `movies` | tmdb_id | ข้อมูลภาพยนตร์: title · release_date · vote_average · vote_count · popularity · overview · added_at |
| `similar_links` | source_id + target_id | ความเชื่อมโยงหนังคล้ายกัน พร้อมคะแนน (score) ใช้ประกอบการจัดอันดับ |
| `watchlist` | movie_id | รายการรับชม อยู่ถาวรข้ามเซสชัน: note · added_at |
| `favorites` | movie_id | รายการโปรด อยู่ถาวรข้ามเซสชัน: note · added_at |
| `searches` | id | ประวัติการค้นหา: query · result_count · searched_at |
| `api_cache` | cache_key | แคชคำตอบจาก TMDB: payload (JSON) · fetched_at · อายุแคช 24 ชั่วโมง (cache_key = พาธ+พารามิเตอร์ของคำขอ โดยไม่รวมคีย์ API) |

## 4. คำสั่งของระบบ (Command Specification)

| คำสั่ง | อินพุต | พฤติกรรมที่คาดหวัง |
|---|---|---|
| `search <ชื่อเรื่อง>` | ข้อความ | ค้นหาจริงจาก TMDB (ผ่านแคช) แสดงผลไม่เกิน 10 รายการแรก · บันทึกประวัติลง `searches` · ไม่พบ → แจ้งให้ทราบ |
| `discover <รหัส> [ตัวเลือก]` | จำนวนเต็มมากกว่า 0 + ตัวเลือกด้านล่าง | ดึง similar + recommendations รวมกัน ตัดรายการซ้ำ กรอง/เรียงตามตัวเลือก บันทึกผลลง `movies`/`similar_links` แล้วแสดงผล |
| ↳ `--min-rating` | คะแนน 0–10 | กรองคะแนนขั้นต่ำ |
| ↳ `--min-votes` | จำนวนเต็ม | กรองจำนวนโหวตขั้นต่ำ |
| ↳ `--year` | ปี เช่น `2020` หรือช่วง `1990-2020` | กรองตามช่วงปีที่ฉาย (วันฉายไม่ทราบ = ถูกตัดเมื่อกำหนดช่วงปี) |
| ↳ `--sort` | `rating` \| `votes` \| `year` \| `popularity` | เรียงลำดับจากมากไปน้อยตามฟิลด์ที่เลือก (ค่าเริ่มต้น `rating`) |
| ↳ `--limit` | จำนวนเต็ม | แสดงผลไม่เกิน N รายการแรก (ค่าเริ่มต้น 10) |
| `watchlist add\|list\|remove <รหัส>\|clear` | จำนวนเต็มมากกว่า 0 | จัดการรายการรับชมในฐานข้อมูล — ไม่เพิ่มซ้ำ; ถ้ารหัสยังไม่อยู่ในฐานข้อมูล ระบบดึงข้อมูลจาก TMDB ก่อนเพิ่ม |
| `favorites add\|list\|remove <รหัส>` | จำนวนเต็มมากกว่า 0 | จัดการรายการโปรดในฐานข้อมูล — ไม่เพิ่มซ้ำ; ดึงจาก TMDB อัตโนมัติถ้ายังไม่มี |
| `export watchlist` / `export favorites` | ชื่อรายการ | เขียนไฟล์ CSV ลงโฟลเดอร์ `data/` (watchlist.csv / favorites.csv) แล้วแจ้งที่อยู่ไฟล์ |
| `history [N]` | จำนวนเต็ม (ไม่บังคับ) | แสดงประวัติการค้นหาล่าสุด N รายการจากตาราง `searches` (ค่าเริ่มต้น 10) |
| `help` | — | แสดงคำสั่งทั้งหมด (อัปเดตรวมคำสั่งใหม่) |
| `quit` / `exit` / `q` / `ออก` | — | ออกจากโปรแกรมทันที ไม่ว่าพิมพ์แบบใด |

## 5. Definition of Done (DoD)

**การทำงานปกติ**

- [ ] `search` กับ TMDB จริง: ผลลัพธ์ถูกต้องตามที่ TMDB ตอบ และถูกบันทึกใน `searches`
- [ ] ค้นคำเดิมซ้ำภายในอายุแคช: ระบบใช้ผลจาก `api_cache` โดยไม่เรียก API ซ้ำ (พิสูจน์ด้วยเทสต์)
- [ ] `discover` กับทุกตัวเลือกกรอง/เรียง: ผลลัพธ์ตรงเงื่อนไขและลำดับถูกต้อง (พิสูจน์ด้วยเทสต์ข้อมูลจำลอง)
- [ ] `watchlist` และ `favorites`: add → list → remove → clear ทำงานครบถ้วน และไม่เพิ่มรายการซ้ำ
- [ ] ปิดโปรแกรมแล้วเปิดใหม่: รายการรับชมและรายการโปรดยังอยู่ครบ (SQLite ถาวร)
- [ ] `export` สร้างไฟล์ CSV ใน `data/` เปิดอ่านได้ หัวคอลัมน์และข้อมูลถูกต้อง (รองรับข้อความที่มีคอมมา/อักขระพิเศษ)
- [ ] `history` แสดงประวัติการค้นหาล่าสุดตามจำนวนที่กำหนด

**กรณีผิดพลาดและขอบเขต**

- [ ] ไม่มีคีย์ `TMDB_API_KEY`: โปรแกรมไม่หยุดทำงาน — คำสั่งที่ต้องใช้ API แจ้งวิธีตั้งค่าคีย์อย่างชัดเจน ส่วนคำสั่งอื่นยังใช้งานได้ตามปกติ
- [ ] เน็ตหลุด / timeout: แจ้งข้อความสุภาพและกลับสู่เมนูได้
- [ ] คีย์ผิด (401): แจ้งสาเหตุชัดเจน
- [ ] ถูกจำกัดอัตราการเรียก (429): แจ้งให้รอแล้วลองใหม่
- [ ] ค้นหาไม่พบ / รหัสไม่มีใน TMDB (404): แจ้งข้อความอ่านง่าย ไม่ใช่ error ดิบ
- [ ] รหัสผิดรูปแบบ (`abc` · `-3` · `0`) · คำสั่งว่าง · คำสั่งไม่รู้จัก: พฤติกรรมเหมือน Sprint 1 ทุกประการ
- [ ] เขียนไฟล์ CSV ไม่สำเร็จ (โฟลเดอร์ไม่มีสิทธิ์เขียน): แจ้งข้อความ ไม่หยุดทำงาน
- [ ] ไฟล์ฐานข้อมูลถูกลบ: เปิดโปรแกรมใหม่แล้วสร้างฐานข้อมูลใหม่ให้อัตโนมัติ ทำงานต่อได้ทันที

**คุณภาพโค้ด**

- [ ] โค้ดผ่าน flake8 และทุกเมธอดมี docstring
- [ ] pytest ผ่านทั้งหมด — ชุดเดิม 40 เคส (ปรับให้ทำงานกับ Mock API) + เคสใหม่ของ Sprint 2 — โดยไม่ต้องใช้อินเทอร์เน็ต
- [ ] CI (GitHub Actions) เขียวต่อเนื่อง

## 7. แผนการทดสอบ (Test Plan)

ทดสอบด้วยสองช่องทางตามวงรอบ Sprint

1. **ชุดทดสอบอัตโนมัติ (pytest) แบบ Mock API** — ครอบคลุมทุกโมดูล: `movie_store` (6 ตาราง · แคช · favorites/searches) · `tmdb_client` (แคช hit/miss และกรณีผิดพลาด 401/404/429/timeout/JSON เสีย) · `discovery` (ทุกตัวเลือกกรอง/เรียง) · `exporter` (CSV รวมอักขระพิเศษ) · `cli` (คำสั่งทั้งหมดผ่าน Mock client และฐานข้อมูลชั่วคราว) — ห้ามเรียกอินเทอร์เน็ตจริงในเทสต์
2. **การรันจริงกับ TMDB** — เก็บบันทึกเซสชันสาธิต: ค้นหา → discover พร้อมกรอง → เพิ่ม watchlist/favorites → ปิดและเปิดโปรแกรมใหม่ (ข้อมูลยังอยู่) → export CSV และเปิดไฟล์ — พร้อมกรณีผิดพลาด (ไม่มีคีย์ · เน็ตหลุด · 404 · 429)
3. **CI** — ต่อยอด workflow เดิม (flake8 → pytest) ให้ครอบชุดทดสอบที่เพิ่มขึ้น โดยยังไม่ต้องใช้คีย์
